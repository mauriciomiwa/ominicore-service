O que é

Serviço interno de notificações multicanal da casa, em Go 1.27, arquitetura hexagonal. Hoje (change 01-enviar-email, em curso) cobre o pedido por Template e o envio pelo Canal Email.

Como está organizado

graph LR
  S[Sistemas de origem] -->|POST /v1/notificacoes| API[ominicore api]
  API --> APP[aplicacao: SendMessageUseCase]
  W[ominicore worker] --> DESP[aplicacao: DespacharUseCase]
  APP --> DOM[dominio: Template, NotificationRouter]
  DESP --> DOM
  APP & DESP --> PG[(Postgres ominicore)]
  DESP --> SG[SendGrid]
  API --> KC[Keycloak JWKS]
  API --> RD[(Redis: cache JWKS)]
  API & W --> BAO[OpenBao: segredos no boot]

Camadas: internal/dominio (sem dependência externa) · internal/aplicacao e internal/portas · internal/adaptadores/{entrada,saida}/* · cmd/ominicore (subcomandos api, worker, migrate). A fronteira é conferida pelo depguard (.golangci.yml).

Configuração

O inventário só detectou SENDGRID_API_KEY/SENDGRID_REMETENTE (lidas pelo deploy/local/bootstrap.sh). As OMINICORE_* são lidas por cmd/ominicore/main.go (lerConfig, via função env — o scanner não as vê); lista completa em deploy/local/README.md. Nenhuma tem .env declarado: vão para o Infra/AMBIENTES.md no primeiro deploy.

Pontos de atenção

  • ReservarTentativa segura a transação durante a chamada ao SendGrid (até 10 s): simples e seguro contra queda, mas cada worker ocupa uma conexão por envio — revisar se o volume crescer (ADR 0001).
  • O NotificationRouter desta fatia encerra a Notificação em qualquer falha; retry e fallback chegam na fatia 02.

sequenceDiagram
